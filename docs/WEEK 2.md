## Итог недели

Серверная часть реализована и закрывает все функциональные требования MVP: CRUD заметок, пространства, теги, полнотекстовый поиск, фильтры и сортировку, закреп и вложения. Данные пользователей пока не изолированы друг от друга: каждый запрос к базе ограничен текущим пользователем, обращение к чужому объекту возвращает `404`.

API описан в OpenAPI-схеме и доступен в Swagger UI по адресу `/api/docs/`, поэтому фронтенд может работать по живой документации, а не по устным договорённостям.

## Авторизация (в стадии реализации)

Используется `djangorestframework-simplejwt`. По умолчанию для всего API включены `JWTAuthentication` и `IsAuthenticated`; без токена открыты только регистрация, вход и обновление токена.

- `POST /api/auth/login` по email и паролю возвращает пару `access` + `refresh`.
- `POST /api/auth/refresh` выдаёт новый `access`; включён `ROTATE_REFRESH_TOKENS`, старый `refresh` после ротации уходит в blacklist.
- `POST /api/auth/logout` помещает `refresh` в blacklist, после чего обновить сессию им уже нельзя (FR-01). `access` живёт недолго, поэтому сессия гаснет вскоре после выхода.

## Поиск, фильтры, сортировка

Фильтрация вынесена в `NoteFilter` (`django_filters.FilterSet`, файл `notes/filters.py`).

| Параметр            | Что делает                                               |
| ------------------- | -------------------------------------------------------- |
| `search`            | полнотекстовый поиск по заголовку и тексту               |
| `space`             | заметки одного пространства                              |
| `tags`              | id тегов через запятую, например `1,4`                   |
| `ordering`          | `created_at`, `updated_at`, `-created_at`, `-updated_at` |
| `page`, `page_size` | пагинация                                                |

Все параметры комбинируются в одном запросе:

```
GET /api/notes?search=отчёт&space=3&tags=1,4&ordering=-updated_at&page=2
```

**Поиск** (FR-05) построен на встроенном полнотекстовом поиске PostgreSQL с русской конфигурацией, поэтому он находит словоформы: по запросу «заметки» находится «заметка». Каждое слово запроса превращается в префиксное условие, так что поиск работает и по началу слова. Заголовку присвоен больший вес, чем тексту, и результаты ранжируются по релевантности. Запрос использует GIN-индекс, это закрывает требование к скорости ответа (NFR-01). Отдельный поисковый движок вроде Elasticsearch не понадобился.

**Закреп** (FR-07) — это `PATCH /api/notes/{id}` с телом `{"is_pinned": true}`. Сортировка всегда начинается с `-is_pinned`, а уже затем применяется выбранный `ordering`, поэтому закреплённые заметки остаются наверху при любой сортировке.

## API

Все адреса начинаются с `/api/`, тела запросов и ответов — JSON в `snake_case`, даты — ISO-8601.

| Метод                   | Адрес                     | Действие                                                      |
| ----------------------- | ------------------------- | ------------------------------------------------------------- |
| POST                    | `/auth/register`          | регистрация `{email, password, name}`                         |
| POST                    | `/auth/login`             | вход, ответ `{access, refresh}`                               |
| POST                    | `/auth/refresh`           | новый `access` по `refresh`                                   |
| POST                    | `/auth/logout`            | выход, `refresh` в blacklist                                  |
| GET, POST               | `/notes`                  | список с фильтрами / создание                                 |
| GET, PUT, PATCH, DELETE | `/notes/{id}`             | одна заметка; закреп через `PATCH`                            |
| GET, POST               | `/notes/{id}/attachments` | вложения заметки, загрузка `multipart/form-data`, поле `file` |
| DELETE                  | `/attachments/{id}`       | удаление вложения                                             |
| GET, POST               | `/spaces`                 | пространства                                                  |
| PUT, DELETE             | `/spaces/{id}`            | переименование / удаление                                     |
| GET, POST               | `/tags`                   | теги                                                          |
| DELETE                  | `/tags/{id}`              | удаление тега                                                 |
| GET                     | `/schema/`, `/docs/`      | OpenAPI-схема и Swagger UI                                    |

Объект заметки в ответе сервера:

```json
{
  "id": 1,
  "title": "Отчёт",
  "content": "текст…",
  "space": 3,
  "tags": [1, 4],
  "is_pinned": false,
  "attachments": [
    {
      "id": 10,
      "file": "/media/attachments/2026/09/a.pdf",
      "uploaded_at": "2026-09-25T12:00:00Z"
    }
  ],
  "created_at": "2026-09-20T09:00:00Z",
  "updated_at": "2026-09-25T12:00:00Z"
}
```

Для разработки фронтенда есть команда `python manage.py seed`, которая заполняет базу тестовыми пользователями, пространствами, тегами и заметками.

## Покрытие требований

| ID     | Требование                   | Как реализовано                                                                   |
| ------ | ---------------------------- | --------------------------------------------------------------------------------- |
| FR-01  | Регистрация, вход, выход     | `accounts`, JWT, blacklist refresh-токенов при выходе                             |
| FR-02  | CRUD заметок                 | `NoteViewSet`, `updated_at` обновляется автоматически                             |
| FR-03  | Пространства                 | `SpaceViewSet`, уникальность имени в рамках пользователя, `SET_NULL` при удалении |
| FR-04  | Теги                         | `TagViewSet`, связь `ManyToMany` с заметками                                      |
| FR-05  | Поиск                        | полнотекстовый поиск PostgreSQL, русская морфология, префиксный поиск             |
| FR-06  | Фильтры и сортировка         | `NoteFilter`: `space`, `tags`, `ordering`, комбинируются с `search`               |
| FR-07  | Закреп                       | `is_pinned` через `PATCH`, всегда первым ключом сортировки                        |
| FR-08  | Вложения                     | `Attachment`, загрузка и удаление, файлы чистятся сигналом                        |
| NFR-01 | Поиск быстрее 1 секунды      | GIN-индекс по `tsvector`                                                          |
| NFR-02 | Хеш паролей, изоляция данных | хеширование Django, фильтр по `request.user`, `404` на чужой id                   |
