## Бэкенд

### Что доделано по сравнению с неделей 2

| Что | Как реализовано |
|-----|-----------------|
| База данных | PostgreSQL, параметры подключения читаются из `.env` через `python-dotenv` |
| Пользователь | `accounts.User` с входом по email; `UserManager` нормализует email и хеширует пароль |
| Авторизация | `simplejwt`: `access` живёт 30 минут, `refresh` — 7 дней, включены `ROTATE_REFRESH_TOKENS` и `BLACKLIST_AFTER_ROTATION` |
| Выход | `LogoutView` кладёт `refresh` в blacklist и отвечает `204`; на неверный токен — `400` |
| Регистрация | `RegisterSerializer`, пароль только на запись, минимум 8 символов |
| Изоляция данных | все queryset фильтруются по `request.user`, плюс `IsOwner` на уровне объекта |
| Чужие связи | `NoteSerializer.validate()` запрещает привязать к заметке чужое пространство или тег (`400`) |
| Админка | модели зарегистрированы в Django Admin |
| Тестовые данные | команда `seed` создаёт пользователя `demo@example.com`, пространство, тег и заметку |

### Поиск

Поиск по `search` объединяет два условия:

- полнотекстовый поиск PostgreSQL с конфигурацией `russian` по заголовку и тексту — находит словоформы («заметки» → «заметка»);
- поиск подстроки без учёта регистра (`icontains`) — находит по части слова («замет» → «заметка»).

Полнотекстовая часть опирается на GIN-индекс `note_search_gin` по `SearchVector("title", "content", config="russian")`.

### Сортировка и фильтры

- `ordering` принимает только `created_at`, `updated_at` и варианты с минусом. Любое другое значение безопасно заменяется на `-updated_at`.
- Первым ключом сортировки всегда идёт `-is_pinned`, поэтому закреплённые заметки остаются наверху (FR-07).
- `NoteFilter` фильтрует по `space` и по `tags` (id через запятую). Если в `tags` передан мусор, возвращается пустой список, а не ошибка `500`.
- Запросы к списку заметок оптимизированы через `select_related("space")` и `prefetch_related("tags", "attachments")`, чтобы не делать отдельный запрос на каждую заметку.

### Вложения

- `GET/POST /api/notes/{id}/attachments` — список и загрузка файла (`multipart/form-data`). Заметка ищется только среди заметок текущего пользователя, на чужую — `404`.
- `DELETE /api/attachments/{id}` — удаление; доступно только владельцу заметки.
- Сигнал `post_delete` удаляет файл с диска как при удалении вложения, так и при каскадном удалении заметки (FR-08).

## Фронтенд

### Стек

React 19, TypeScript, Vite, React Router 7, TanStack Query 5, axios. Линтер — oxlint, типы проверяются `tsc`.

### Страницы

| Страница | Маршрут | Что умеет |
|----------|---------|-----------|
| `LoginPage` | `/login` | вход по email и паролю |
| `RegisterPage` | `/register` | регистрация |
| `NotesPage` | `/` | список заметок, поиск, фильтр по пространству и тегу, пагинация |
| `NoteEditorPage` | `/notes/new`, `/notes/:id` | создание и редактирование, выбор пространства и тегов, закреп, вложения, удаление |
| `SpacesPage` | `/spaces` | создание, переименование, удаление пространств |
| `TagsPage` | `/tags` | создание и удаление тегов |

Все страницы, кроме входа и регистрации, обёрнуты в `ProtectedRoute`: без токена пользователя отправляет на `/login`.

### Слой API

`src/api/` — единственное место, где фронтенд обращается к серверу. Файлы и функции названы так, как зафиксировано в контракте: `auth.ts`, `notes.ts`, `spaces.ts`, `tags.ts`, `attachments.ts`.

`client.ts` содержит общий экземпляр axios с двумя перехватчиками:

- к каждому запросу добавляется заголовок `Authorization: Bearer <access>`;
- если сервер ответил `401`, клиент один раз пробует обновить `access` через `/auth/refresh` и повторяет запрос. Если обновить не удалось, токены стираются и пользователь попадает на страницу входа.

### Состояние и компоненты

- Хуки `useNotes`, `useSpaces`, `useTags`, `useAuth` поверх TanStack Query. Ключи кеша собраны в `src/lib/queryKeys.ts`, после изменений нужные списки обновляются автоматически.
- Компоненты: `NoteCard`, `NoteList`, `SearchBar`, `FilterPanel`, `TagPicker`, `SpaceSelect`, `AttachmentList`, `PinButton`, `Layout`, `ProtectedRoute`.
- Типы `src/types/index.ts` повторяют объекты API один в один (`Note`, `Space`, `Tag`, `Attachment`, `Paginated<T>`, `NoteFilters`, `AuthTokens`).
- Вёрстка адаптивная: на узких экранах меню прокручивается по горизонтали, отступы уменьшаются (NFR-03).

## Интеграция

Фронтенд и бэкенд сведены по контракту API без доработок формата.

- Dev-сервер Vite проксирует `/api` и `/media` на Django (`127.0.0.1:8000`), поэтому для локальной разработки CORS не нужен.
- Список заметок приходит в формате DRF `{count, next, previous, results}`, фронтенд строит по нему пагинацию.
- Выбранные теги фронтенд передаёт строкой `tags=1,4`, как ожидает `NoteFilter`.
- Закреп отправляется как `PATCH {is_pinned: true}`, файлы — как `multipart/form-data` с полем `file`.
- Swagger UI на `/api/docs/` использовался как общая точка сверки форматов.

Ветки смёржены через pull request: `feature/d-backend` и `feature/c-ui` в `dev` (PR #2, #3), затем `dev` в `main` (PR #4).
